# GEO Analyzer 고도화 설계서 (v2 → v3)

작성일: 2026-06-10 · 대상: geo-analyzer-server v2 (Express + cheerio, 18항목 룰 채점)

---

## 1. 현재 상태 진단

### 구조
```
server.js          Express 라우팅 (analyze/batch/compare/report/health)
lib/scorer.js      18항목 100점 룰 채점 엔진 (cheerio)
lib/reports.js     PDF(pdfkit) · Excel(SheetJS) 리포트
public/index.html  SPA (940줄, 탭 5개 + 동적 결과 탭 3개)
```

### 발견된 결함 (Phase 1에서 수정)
| # | 위치 | 문제 |
|---|------|------|
| B1 | scorer.js `title_length` | `(tl >= 30 \|\| tl <= 80)` — 항상 참. 어떤 길이든 3점 보장되는 버그 (`&&` 의도) |
| B2 | scorer.js `meta_length` | 동일 패턴 버그 `(ml >= 80 \|\| ml <= 200)` |
| B3 | scorer.js JSON-LD | 첫 번째 `<script type="application/ld+json">`만 검사. 언론사 페이지는 보통 다수(Organization, BreadcrumbList, NewsArticle...) → Article 스키마 오탐지 |
| B4 | scorer.js 본문 추출 | nav/header/footer 제거 후 **문서 전체 텍스트** 사용 → 추천기사·댓글·광고 문구 혼입. `firstPara = slice(0,200)`이 실제 리드문이 아닌 경우 다수 |
| B5 | scorer.js 링크 분류 | `href.includes(domain)` 문자열 매칭 → `evil.com/?ref=joongang.co.kr` 오분류 |

### 구조적 한계
- 정량 룰만 존재 → "AI가 실제로 인용할 만한가"라는 정성 판단 불가
- 점수와 실제 AI 노출(SoV) 간 상관 검증 수단 없음
- 이력이 브라우저 localStorage에만 존재(30개 제한, 기기 종속) → 시계열 분석 불가

## 2. 고도화 로드맵 (4 Phase)

```
Phase 1  채점 엔진 v2 정교화        [이번 세션 구현] 외부 의존성 없음
Phase 2  Claude AI 정성 분석        [이번 세션 구현] ANTHROPIC_API_KEY 필요
Phase 3  운영 인프라 (DB·시계열)     [구현 완료] node:sqlite 내장 (의존성 0)
Phase 4  실측 SoV 추적              [구현 완료] Perplexity 키 입력 시 활성 (모크 모드 내장)
```

Phase 4(실측 SoV)는 우선순위가 높지만 측정 결과를 **저장·누적**할 DB가 전제이므로 Phase 3 뒤에 배치.

## 3. Phase 1 — 채점 엔진 v2 정교화 ✅

**파일: `lib/scorer.js` 전면 개정 (외부 패키지 추가 없음)**

1. **버그 수정**: B1, B2 (`&&` 보정), B5 (URL 객체 hostname 비교)
2. **본문 추출 개선**: 한국 언론사 우선순위 셀렉터 체인으로 기사 컨테이너 탐지
   `article → [itemprop=articleBody] → #articleBody/#article-view-content-div → .article_body/.news_body/.article-body → og:description 보조` → 실패 시 기존 방식 폴백. 추출 방식을 `meta.extraction`으로 노출해 신뢰도 표시
3. **JSON-LD 전수 검사**: 모든 ld+json 파싱, `@graph` 배열 지원, NewsArticle 우선 탐지
4. **GEO 항목 보강** (GEO 50점 내 재배분, 총점 100 유지):

| 항목 | 변경 |
|------|------|
| fact_numbers | 10 → 8 |
| fact_dates | 8 → 5 |
| ld_json | 7 → 5 |
| **structure_lists** (신규) | 4 — 목록(ul/ol)·표 등 AI 발췌 친화 구조 |
| **question_headings** (신규) | 3 — 질문형 헤딩/FAQ 스키마 (AI 검색 질의 매칭) |

5. **호환성**: 프런트·리포트는 `CRITERIA` 배열 기반 렌더링이라 자동 반영. 응답에 `engineVersion: 2` 추가

## 4. Phase 2 — Claude AI 정성 분석 ✅

**신규 파일 `lib/ai.js` + server.js 라우트 2개 + index.html UI**

| 엔드포인트 | 기능 |
|-----------|------|
| `POST /api/ai/analyze` | 룰 채점 결과 + 본문을 Claude에 전달 → **AI 인용가능성 평가** JSON 반환 |
| `POST /api/ai/rewrite` | 본문 → GEO 최적화 리라이팅 (제목·메타·리드문·본문·JSON-LD). 기존 룰 기반 재작성 패널의 AI 업그레이드 |

**AI 평가 스키마** (5축 정성 평가, 룰 점수와 별도):
```json
{
  "citability": 0-100,
  "axes": { "사실밀도":n, "답변완결성":n, "구조명료성":n, "신뢰신호":n, "고유정보가치":n },
  "strengths": [...], "weaknesses": [...],
  "suggestions": [{ "priority": "high|mid|low", "action": "..." }],
  "predictedQueries": ["이 기사가 인용될 만한 AI 검색 질문들"]
}
```

**운영 방식**
- API 키: `ANTHROPIC_API_KEY` 환경변수 또는 UI(도구 탭)에서 입력 → localStorage 저장, 요청 헤더 `x-anthropic-key`로 전송. 서버에 키 저장 안 함
- 모델: 기본 `claude-fable-5`, `CLAUDE_MODEL` 환경변수로 교체 가능
- SDK 미사용, Node 18+ 내장 fetch로 직접 호출 (의존성 0 추가)
- 키 없으면 룰 채점은 정상 동작, AI 카드만 안내 메시지 (graceful degradation)

**UI**: 결과 탭에 "🤖 AI 정성 분석" 카드 추가 (버튼 클릭 시 호출 — 토큰 비용 고려해 자동 실행 안 함)

## 5. Phase 3 — 운영 인프라 (DB·시계열) ✅

**신규 `lib/db.js` + server.js 라우트 + 이력 탭 개편**

저장소 (설계 변경: better-sqlite3 → 의존성 0 구성):
- 1순위 **node:sqlite** (Node 22.13+ 내장) → `data/geo.db`
- 미지원 환경은 **JSON 파일 폴백** (`data/geo-history.json`) — 동일 인터페이스, 자동 전환
- 경로는 `GEO_DATA_DIR` 환경변수로 변경 가능
- 테이블: `analyses`(전체 스냅샷 JSON 포함), `ai_reviews`, `tracked_urls`, `sov_checks`(Phase 4 예약)

| 엔드포인트 | 기능 |
|-----------|------|
| `GET /api/history` `?limit&q` | 이력 목록 (단일·배치·비교·재분석 모두 자동 저장) |
| `GET /api/history/urls` | 분석된 URL 목록 (횟수 포함) |
| `GET /api/history/:id` | 전체 결과 스냅샷 (클릭 → 결과 재표시) |
| `DELETE /api/history(/:id)` | 개별·전체 삭제 |
| `GET /api/timeseries?url=` | URL별 총점/SEO/GEO 추이 |
| `GET/POST/DELETE /api/track` | 추적 URL 등록·해제 |
| `POST /api/track/run` | 추적 URL 전체 즉시 재분석 |

- 주기 재분석: 의존성 없는 내장 스케줄러 — 매일 `GEO_RECRAWL_HOUR`시(기본 6시) 추적 URL 자동 재분석, `off`로 비활성화 (node-cron 불필요로 설계 변경)
- UI: 이력 탭 서버 전환(서버 불가 시 localStorage 폴백 표시), **📈 URL별 점수 추이 차트**(총점/SEO/GEO 라인), **🔁 추적 URL 관리** 카드
- AI 정성 분석 결과도 `ai_reviews`에 누적 → Phase 4에서 점수-인용 상관 분석에 활용

## 6. Phase 4 — 실측 SoV 추적 ✅

**신규 `lib/sov.js` + 라우트 7개 + "📡 SoV 실측" 탭**

흐름: 키워드 등록 → Perplexity API(sonar, 인용 URL 반환) 질의 → 인용 출처 hostname을 자사/경쟁사 도메인과 매칭 → `sov_checks`에 누적 → SoV(%)·추이·상관 산출

| 엔드포인트 | 기능 |
|-----------|------|
| `GET/PUT /api/sov/config` | 자사·경쟁사 도메인, 엔진 설정 (URL 입력해도 도메인 자동 정규화) |
| `GET/POST/DELETE /api/sov/keywords` | 측정 키워드 관리 |
| `POST /api/sov/run` | 전체 키워드 즉시 측정 (키: 헤더 `x-perplexity-key` 또는 `PERPLEXITY_API_KEY`) |
| `GET /api/sov/summary` | 현재 자사/경쟁사 SoV, 일자별 추이, 키워드별 최신 결과, 점수-인용 상관 |
| `GET /api/sov/checks` | 원본 측정 기록 |

- **키 미발급 대응**: 키가 없으면 안내 메시지로 안전 동작. `GEO_SOV_MOCK=1`로 가짜 인용을 생성하는 **모크 모드** 내장 — 키 발급 전 전체 플로우 체험 가능. 키는 UI(SoV 탭)에서 입력(localStorage)하거나 환경변수로 설정
- **주기 측정**: 추적 재분석과 동일한 내장 스케줄러 — 매일 `GEO_SOV_HOUR`시(기본 6시) 자동 측정 (서버 환경변수 키 필요)
- **점수-인용 상관**: 인용된 자사 URL과 분석 이력(`analyses`)을 매칭해 인용/미인용 평균 GEO 점수 비교 → 채점 가중치 보정 근거
- 제약: ChatGPT/Gemini는 공식 인용 API 없음 → Perplexity 우선. `lib/sov.js`의 `queryPerplexity`만 교체하면 타 엔진 확장 가능

## 8. 추가 고도화 ① — 색인·인용 차단 게이트 ✅ (2026-09-21, engine v3)

참고: leopard627/fire-your-seo-agency의 "noindex 최우선 점검" 원칙

- `lib/scorer.js`: `detectIndexability()` 신규. `<meta name="robots|googlebot|googlebot-news|bingbot|yeti|naverbot">`와 `X-Robots-Tag` 헤더를 읽어 판정
  - `noindex`·`none`·HTTP 4xx 이상 → **blocked(인용 불가)**
  - `nosnippet`·`max-snippet:0` → **limited(인용 제한)**, `data-nosnippet` 영역 수는 참고로 표시
  - 점수는 바꾸지 않음(이력 비교 호환). 결과에 `indexability` 필드 추가, `engineVersion: 3`
- `server.js`: `fetchURL()`이 `{ html, headers, status }`를 반환하도록 변경 → 단일·배치·비교·추적 재분석 모두 헤더까지 검사
- `public/index.html`: 결과 상단 경고 배너, 배치·비교 화면에 ⛔/⚠ 배지. HTML 붙여넣기 분석은 헤더 미확인 안내
- `lib/reports.js`: PDF 상단 경고 문구, Excel 요약 시트 "색인·인용" 열
- `test/smoke.js`: 게이트 테스트 10건 추가 (전부 통과). 원본은 `geo-analyzer-server/_backup_v3_20260921/`

## 9. 추가 고도화 ② — JSON-LD·화면 내용 일치 검사 ✅ (2026-09-21)

- 신규 GEO 항목 `ld_consistency`(3점): Article 계열 JSON-LD의 headline·author·datePublished가 화면의 제목(H1/title/og:title)·바이라인·표시 날짜와 맞는지 항목당 1점
  - 제목은 2글자 단위 유사도 0.6 이상이면 일치. 제목 끝 "- 매체명", 엔디소프트 CMS의 "< 섹션 < 기사본문" 접미사 제거
  - 저자는 "기자·특파원" 호칭 제외 후 화면 텍스트(스크립트 제외)에서 탐색
  - 날짜는 2026.09.21 / 2026-09-21 / 2026년 9월 21일 표기 모두 인식, UTC 시각은 한국시간 날짜로 환산
  - dateModified가 datePublished보다 이르면 1점 감점, dateModified 없으면 안내만
- 배점 조정: `ld_json` 5→4, `article_schema` 8→6 (GEO 50·총점 100 유지)
  - ⚠ 이전 이력과 비교 시 JSON-LD가 있는 기사는 최대 3점 차이가 날 수 있음(엔진 v3 기준)
- 재구성 패널: 불일치 항목을 목록으로 안내, 화면과 다른 headline은 화면 H1으로 교체한 코드 제시. LD가 없을 때 만드는 코드는 오늘 날짜 대신 페이지에서 찾은 실제 발행일·저자만 사용(없으면 [ ] 자리표시)
- 실사: 매체A 기사(2026-09-21 확인)는 JSON-LD가 `"@type":"Person","name":"매체A"` 한 블록뿐 — NewsArticle 없음, 매체를 사람으로 선언
- 테스트: 일치 검사 10건 + 매체A 실제 구조 2건 추가, 전부 통과

## 10. 추가 고도화 ③ — 문단 단위 인용 가능성 ✅ (2026-09-21)

- 신규 GEO 항목 `para_citability`(4점) — 본문의 모든 문단(40자 이상, `<p>` 또는 `<br><br>` 분리)을 검사
  - 독립성(2점): 지시어로 시작하는 문단 비율. "이는·이에·이번·해당·그는·이 회사" 등. 접속어("또·아울러·한편·앞서")는 떼어낸 뒤 판정("한편 바사제약는"=통과, "아울러 이번 승인은"=지적). "[매체A ○○○ 기자]" 머리말은 제외. 80% 이상 2점, 60% 이상 1점
  - 수치 기준 시점(2점): %·억원·명·건 등 통계 수치가 있는 문단에 연도·분기·"기준" 같은 기준 시점이 있는지. "올해·지난해" 같은 상대 표현은 절반만 인정. "1회 이상·6개월" 같은 조건·용법 표현은 수치로 보지 않음. 70% 이상 2점, 40% 이상 1점
- 배점 조정: `first_para` 10→6 (숫자 3·고유명사 2·100자 이상 1), GEO 50·총점 100 유지
  - ⚠ 이전 이력과 비교 시 첫 문단 점수가 높던 기사는 점수가 달라질 수 있음
- 결과 `paragraphs` 필드: 문단 수, 독립 비율, 기준 시점 비율, 문단 번호별 지적(최대 12건)
- 재구성 패널 본문 칸에 "문단 단위 인용 점검" 목록(문단 번호·원문 앞부분·고칠 방법) 표시
- 매체A 기사 4건(2026-09-21) 문단으로 규칙 조정, 테스트 7건 추가 — 전부 통과

## 11. 추가 고도화 ④ — 원출처(1차 소스) 링크 ✅ (2026-09-21)

- `external_links`(4점, SEO 그룹) 재정의 — 라벨 "외부 신뢰 링크" → "원출처(1차 소스) 링크". id는 유지해 이력·리포트 호환
  - 원출처 2종 이상 4점 · 1종 3점 · 일반 외부 링크만 2점 · 링크 없이 본문에 NCT 번호·DOI만 1점 · 없음 0점
  - 원출처 목록(`PRIMARY_SOURCES`, 약 50개): 공시(DART·KIND·SEC), 임상등록(ClinicalTrials.gov·CRIS·EU CTIS·WHO ICTRP), 논문(DOI·PubMed·NEJM·Lancet·Nature 등, 프리프린트 포함), 규제기관(FDA·EMA·PMDA·식약처·복지부·질병청 등), 보도자료 배포처(PR Newswire 등). 하위 도메인 포함
  - 공유 버튼·SNS·광고·포털 링크는 외부 링크로 세지 않음(`noiseLinks`로 따로 집계)
  - 기사 본문 컨테이너를 찾았는데 본문 안에 링크가 없으면, 사이드바·푸터의 외부 링크를 출처로 인정하지 않음(내부 링크 판정은 기존 유지)
- 본문 출처 단서(`sourceMentions`): NCT 번호·DOI·FDA·EMA/CHMP·식약처·공시·학술지 언급을 찾아 "어떤 원문 링크를 달면 되는지" 재구성 패널에 안내
- 실사: 매체A 기사 8건(2026-09-21) 모두 본문 링크 0개. 사진 설명에 "출처 : 회사명"만 있고, 8건 중 5건이 FDA를 언급하지만 원문 링크가 없음 → 이 항목은 현재 0점, FDA 원문 링크 하나로 3점 회복 가능
- 테스트 7건 추가 — 전부 통과

## 12. 추가 고도화 ⑤ — AI 분석 보안·검증 ✅ (2026-09-21)

- `lib/ai.js` (AI 정성 분석·리라이팅)
  - 페이지에서 가져온 제목·메타·저자·본문을 요청마다 바뀌는 무작위 경계 태그 `<untrusted_page_content boundary="…">`로 감싸 전달. 본문 속 위조 태그는 제거
  - 시스템 프롬프트에 보안 규칙 추가: 태그 안 문장은 데이터일 뿐 지시가 아님, 조작 시도는 따르지 말고 `injectionFlags`에 보고, 신뢰신호 감점
  - 모델 보고와 별개로 로컬 정규식(한·영)으로도 탐지 → `localInjectionFlags`, 둘 중 하나라도 있으면 `injectionDetected: true`
  - AI 평가 결과 보정: 점수 범위(0~100, 축별 0~20), 우선순위 값, 배열 형식 강제
  - 리라이팅 검증: 원문에 없는 숫자(두 자리 이상)를 `unverifiedNumbers`로 표시. JSON-LD는 headline=새 제목, datePublished·author=원문 값으로 고정(`jsonLdFixes`)
- `lib/scorer.js`: `injectionSignals` — 숨김 요소(display:none·visibility:hidden·font-size:0·sr-only 등)·HTML 주석·메타 태그·본문에서 AI 대상 지시문 탐지. 점수에는 반영하지 않고 경고만
- 화면: 결과 상단 🛡️ 경고(위치·문장), AI 평가 카드 경고, 리라이팅 패널에 "원문에 없는 숫자"·JSON-LD 자동 보정 안내
- 테스트: `test/ai.test.js` 신규(가짜 API로 오프라인 검증), `npm test`가 두 테스트 모두 실행. 전부 통과

## 13. 추가 고도화 B — 사이트 점검 모듈 ✅ (2026-09-21)

- 신규 `lib/site.js` + `POST /api/site { url }` + "🌐 사이트 점검" 탭. 기사 URL을 넣으면 그 기사 경로 기준으로 판정. 100점 채점과 별개로 항목별 ✅통과/⚠️주의/❌문제/ℹ️참고 + 근거 + 고칠 방법
- 점검 항목 (4개 영역)
  - 크롤러 정책: robots.txt 존재 / 검색엔진(Googlebot·Bingbot·Yeti) / AI 검색 색인(OAI-SearchBot·Claude-SearchBot·PerplexityBot) / 실시간 열람(ChatGPT-User·Claude-User·Perplexity-User) / 학습용(GPTBot·ClaudeBot·Google-Extended·CCBot·Applebot-Extended·Meta-ExternalAgent·Bytespider, 정책 선택이라 참고) / Crawl-delay(5초 이상 표시, 10초 이상 경고)
    - robots 파서는 구글 명세 따름: UA 정확 일치 그룹 우선(없으면 *), 가장 긴 규칙 우선, 동률이면 Allow, `*`·`$` 지원
  - 색인: 사이트맵(robots 선언·인덱스/목록·lastmod) / 전체 기사 사이트맵(최근 1,000개 이하만 있으면 경고) / 뉴스 사이트맵 / 없는 주소 404 여부(soft 404) / JS 없이 본문 보임(SSR)
  - AI 안내: llms.txt (HTML 오류 페이지를 200으로 주는 경우 구분)
  - 엔티티: 매체 Organization(@id·sameAs·logo·url, Person으로 잘못 선언 감지) / 기자 Person(url·sameAs)
  - 네이버·빙: 서치어드바이저·빙 소유확인 메타(없으면 참고 — 다른 방식 인증 가능) / OG 태그 / 모바일 viewport(고정 폭 경고)
- 테스트 `test/site.test.js`(가짜 사이트 3종: 매체A형·문제 사이트·접속 불가) — 전부 통과. `npm test`에 포함

## 14. 추가 고도화 C — 측정 루프 ✅ (2026-09-21)

"고쳤다"가 아니라 "숫자가 움직였다"까지 확인하는 절차를 도구로 옮김. 신규 `lib/measure.js`, `lib/db.js`에 `experiments`·`crawler_days` 테이블(sqlite·JSON 폴백 모두), "🧪 측정 루프" 탭.

1. **개선 실험** (`/api/exp`)
   - 기준선 기록: 지금 상태를 채점해 저장 + 인용 확인 질문 등록(SoV 키워드에도 자동 추가)
   - "수정 완료" → 재측정일 예약(기본 14일, `GEO_REMEASURE_DAYS`)
   - 재측정: 서버가 켜져 있으면 예약일 이후 매일 `GEO_RECRAWL_HOUR`시에 자동, 버튼으로 즉시도 가능
   - 보고서: `[기준선] [변경] [재측정 예약] [재측정 결과]` 4줄 + 항목별 점수 변화 + 인용 변화(수정 전 28일 ~ 수정 시점 vs 수정 이후, 질문·엔진별 최신값) + 경고(엔진 버전 다름·14일 전 재측정·인용 기록 없음). 복사 버튼
2. **수동 인용 기록** (`/api/citations/manual`): ChatGPT 검색·구글 AI 개요·네이버 AI 브리핑·Perplexity·Copilot·Gemini·Claude. `sov_checks`에 `manual:엔진` 으로 저장. 기존 SoV 자동 측정 지표(currentSov·추이)는 API 결과만으로 계산하도록 분리
3. **엔진별 인용 현황**: `/api/sov/summary`에 `engines`(엔진별 인용률·마지막 기록일·낡음) 추가
4. **낡은 데이터 가드**: 마지막 기록이 14일(`GEO_STALE_DAYS`)보다 오래된 엔진은 "낡음" 표시·흐리게. 크롤러 로그는 7일, LLMO는 분기(92일) 기준
5. **LLMO 분기 점검** (`/api/llmo`): 브라우징 끈 모델(ChatGPT·Claude·Gemini)에 "○○가 뭐야?" → 모름/틀리게 앎/맞게 앎 + 답변 요약. 다음 점검 권장일 표시
6. **AI 크롤러 방문** (`/api/crawlers/import`, `/api/crawlers`): 접속 로그(Apache/Nginx combined, ISO 날짜 로그)를 올리면 날짜·봇별 집계(학습/AI 검색/실시간 열람/검색엔진). 같은 로그 재업로드는 덮어쓰기(중복 없음), 최대 50MB
